# Proposal gameplay demo — October 7, 2026

Latest iteration: each new page load generates three distinct random preferences per character from the attributes represented in the enabled candy pool: one favorite (++), one like (+), one dislike (−). Preferences remain fixed during trades and turn resets; scoring uses those same generated profiles. Names/portraits remain the existing four characters. Encoded catalog profiles are retained as source data but are not used as gameplay preferences. Removed all character preference popup behavior, markup and styling. Portraits and compact preference displays are static sections again; footer says Choose two candies. Low Sugar uses Low sug and Marshmallow uses Mallow in compact labels. Updated verification passes random-profile structure, popup absence, selection preservation and trade behavior at three phone widths. The popup description below documents the superseded iteration.

The single human player selects two candies from different characters and presses **Propose Trade**. The program evaluates both characters. A trade happens immediately only when each character's score change is >= 0, including even/even trades. If either loses points, ownership and all scores remain unchanged. The result panel explains both decisions; **Next proposal**, outside tap or Escape dismisses the resolved result and clears selection. There is no player-controlled confirmation, timer, or additional approval step.

The result shows each character's portrait, preferences, before/after score, direction and Accepts/Declines. Accepted results say Gave/Got; declined results say Offers/Would get and Would be for hypothetical scores. The candies and scoring values are snapshots of the proposal, even after the board ownership has changed. Dismissing a result never reverses or repeats a resolved trade.

Tap either portrait or its short preference box to see name and plain-language Loves/Likes/Dislikes. Desktop mouse hover offers the same information and hides on pointer leave. The next pointerdown anywhere dismisses without consuming the touch's normal action, including the preview shell's toolbar/background. Portrait consultation preserves selected candies. Popups do not intercept pointer events. Character buttons are inaccessible while the result dialog is open; focus is contained on Next proposal, then returned to the first selected slot on dismissal.
